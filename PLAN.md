# Shortcuts for SoundCloud — Implementation Plan

Publisher: ForgedApps LLC · Repo: `ForgedApps/soundcloud-shortcuts` (GitHub) · Targets: Chrome Web Store + Microsoft Edge Add-ons

## 1. Background and what we learned

- The removed extension "SoundCloud Keyboard Shortcuts" is the code at `dy902/soundcloud-hotkeys` (same name, same four commands, last pushed Aug 2022, no license).
- It is Manifest V2 with a non-persistent background page and uses `chrome.tabs.executeScript({code: "..."})` to click player buttons by CSS class. Both the MV2 background page and string-code injection are gone in MV3, so it could not be re-published without a rewrite.
- Edge's Aug 2026 announcement: MV2 extensions are disabled by default for consumers through late 2026, enterprise in early 2027; only MV3 submissions via Partner Center are accepted. Chrome finished its MV2 removal earlier.
- Because the original has no license, we write from scratch and do not copy code. The behavior (four commands, click the player controls) is trivial and not protectable, but a clean-room rewrite avoids any question.

## 2. Product scope

### Phase A — shortcut parity (ship first)
Global keyboard shortcuts for the SoundCloud tab, remappable by the user in the browser's own shortcut page (`chrome://extensions/shortcuts`, `edge://extensions/shortcuts`). This is the `commands` manifest API, which is exactly "configurable in the browser extensions settings area".

Commands (first four get suggested keys; browsers allow at most four suggested keys, the rest are unbound until the user binds them):

| Command | Suggested key | SoundCloud control |
|---|---|---|
| play-pause | Alt+Shift+P | `.playControls__play` |
| next | Alt+Shift+. | `.skipControl__next` |
| previous | Alt+Shift+, | `.skipControl__previous` |
| like | Alt+Shift+L | `.playbackSoundBadge__like` |
| repost | — | `.playbackSoundBadge__repost`-area button |
| seek-back-10 / seek-forward-10 | — | timeline click or `ArrowLeft/Right` key dispatch on player |
| volume-up / volume-down / mute | — | `.volume__button`, volume slider |
| shuffle / repeat | — | `.shuffleControl`, `.repeatControl` |
| focus-soundcloud-tab | — | activates the SoundCloud tab and window |

Behavior details:
- Shortcuts work while the browser has focus on any tab. True OS-wide shortcuts (`"global": true`) are limited by Chrome to Ctrl+Shift+0-9; we expose it as an opt-in note in the options page rather than a default.
- Tab targeting: the tab currently playing audio (`audible: true`) wins, then the most recently used SoundCloud tab. The old extension just took the first match.
- No SoundCloud tab open: optional setting to open one.

### Phase B — Now Playing toolbar icon and popup
- Toolbar action with badge: shows play/pause state via small badge text or icon swap.
- New-track notification: a `chrome.notifications` toast with artwork, title, artist, and buttons (Next, Like). This is the "small popup when a new track plays". Browsers do not allow an extension to pop its toolbar popup programmatically in a reliable, cross-browser way (`action.openPopup` is Chrome-only and recent), and they do not expose toolbar-icon hover at all, so the notification is the dependable mechanism. User can turn it off or set a duration.
- Clicking the icon opens the popup: artwork, title, artist, like/repost state, play/pause, prev/next, elapsed/total time, and a waveform that mirrors SoundCloud's look. Clicking or dragging on the waveform seeks. Hovering shows the time at the cursor like the site does.
- Waveform data: SoundCloud serves per-track waveform JSON (`waveform_url`, 1800 samples). The content script obtains the current track's metadata from the page (hydration data or the player's track link, then one fetch of the track page or the waveform URL), caches it per track in `chrome.storage.session`, and the popup renders it on a canvas. Fallback when unavailable: a plain progress bar styled like SoundCloud's mini player.
- Popup updates live (every ~500 ms) via a port connection to the service worker; the content script pushes position and state changes from a `MutationObserver` on the player bar.

### Later ideas (not in scope now)
Mini overlay on non-SoundCloud pages, scrobbling, Firefox build (WXT makes this cheap), playlist controls.

## 3. Architecture (Manifest V3)

```
src/
  manifest (generated by WXT)          permissions: scripting, storage, notifications, alarms(if needed)
                                        host_permissions: https://soundcloud.com/*
  entrypoints/
    background.ts                       service worker: commands → messages, tab selection, badge,
                                        notifications, state store, popup port
    soundcloud.content.ts               runs on soundcloud.com: player adapter + MutationObserver,
                                        responds to control messages, reports now-playing state
    popup/                              Now Playing UI (vanilla TS or Preact + canvas waveform)
    options/                            settings: notifications on/off + duration, tab-targeting rule,
                                        seek/volume step, open-tab-if-none, link to browser shortcut page
  lib/
    player-adapter.ts                   single file with all SoundCloud DOM selectors + actions
    waveform.ts                         fetch/cache/render waveform samples
    messages.ts                         typed message schema shared by all contexts
    state.ts                            NowPlaying type + storage helpers
```

Key decisions:
- **WXT framework** (Vite + TypeScript): generates MV3 manifest, hot reload, one command to build Chrome and Edge zips, Firefox for free later. pnpm as package manager (installed: Node 22, pnpm 10).
- **All DOM knowledge in `player-adapter.ts`.** SoundCloud class names change; keeping them in one file with a smoke test makes breakage a one-file fix. Prefer `aria-label`/`title` based selectors where stable, with class-name fallback.
- **Service worker does no DOM work.** It sends typed messages to the content script; `chrome.scripting.executeScript({ func })` is only used as a fallback when the content script is not yet injected (tab loaded before install/update).
- **State in `chrome.storage.session`** so the worker can be killed and restored without losing now-playing state.
- No remote code, no analytics, no external servers. Only network calls: SoundCloud's own waveform JSON for the current track. This keeps the store privacy disclosure trivial.

## 4. Store-readiness checklist

Naming and branding
- Name: "Shortcuts for SoundCloud" (or "Now Playing for SoundCloud" once Phase B lands). Both stores' policies forbid names that imply affiliation; "X for SoundCloud" is the accepted pattern, "SoundCloud X" is the risky one the original used.
- Icon: original artwork (cloud + waveform + key motif in ForgedApps colors). Do not use SoundCloud's logo; that is a trademark rejection risk and SoundCloud's brand guidelines prohibit it.
- Description states clearly it is an independent project not affiliated with SoundCloud.

Policy requirements
- Single-purpose statement: "Keyboard shortcuts and a now-playing panel for soundcloud.com."
- Per-permission justifications (scripting, storage, notifications, host permission) written in `docs/store-listing.md` and pasted into both dashboards.
- Privacy policy page hosted in the public `ForgedApps/docs` repo (GitHub Pages). Content: no data collected, no data leaves the browser.
- Minimum permissions: no `tabs`, no `<all_urls>`, no `activeTab` needed.
- Edge: submit the same zip via Partner Center; Edge needs its own 300x300 logo and screenshots at its sizes.

Assets
- Icons 16/32/48/128 plus 300x300 for Edge; 1280x800 screenshots (shortcut page, notification, popup); 440x280 small promo tile for Chrome.

Accounts (user action)
- Chrome Web Store developer account for ForgedApps ($5 one-time, needs a Google account + 2FA, verified publisher email).
- Microsoft Partner Center developer account (free) under the LLC.

## 6. Risks and mitigations

- **SoundCloud markup changes** break selectors. Mitigation: single adapter file, nightly selector smoke test, aria-based selectors first, graceful "control not found" badge.
- **Waveform data access.** The JSON endpoint has been stable for years but is undocumented. Mitigation: progress-bar fallback is always present; waveform is an enhancement.
- **Service worker lifetime.** MV3 workers stop after ~30 s idle; command handling is event-driven so this is fine. Popup keeps a port open while visible, and state lives in `storage.session`.
- **Edge differences.** `commands` and `notifications` are supported; `action.openPopup` is not relied on. Test every step in both browsers.
- **Trademark review.** Use the "for SoundCloud" name pattern and original icon from day one so no resubmission is needed.
- **Ownership of the old listing.** We cannot take over the removed listing's install base; this is a new listing. Optionally reach out to dy902 to link to the new one from their README.
